share.acknowledgement.mode
implicit — records are automatically acknowledged when poll() is called. No explicit ack needed.

explicit — the application must call acknowledge(record, AcknowledgeType) for each record. Enables ACCEPT, RELEASE, REJECT, and RENEW outcomes.

The maximum number of records returned in a single poll() call. Higher values mean larger batches per consumer per tick, increasing throughput but reducing fairness across consumers.
share.acquire.mode
batch_optimized — the broker may return fewer than max.poll.records to optimise batching efficiency (KIP-1206).

record_limit — strictly enforces max.poll.records; the broker will not return more than this count.
Delivery Config
share.delivery.count.limit 5
2510
The maximum number of times a record will be delivered before it is moved to ARCHIVED state and no further delivery attempts are made. Broker bounds: min 2, max 10 (KIP-1240). Records approaching this limit are highlighted in red.
share.renew.acknowledge.enable
When enabled, consumers can send a RENEW acknowledgement to extend the acquisition lock on a record they are still processing (KIP-1222). When disabled, RENEW is rejected — consumers must settle within the original lock window.

Apache Kafka 4.0 introduced Share Groups (KIP-932), enabling true queue semantics alongside Kafka's existing stream processing model. Unlike consumer groups, multiple consumers in a share group can compete for records from the same partition — making it straightforward to scale processing without repartitioning.

This visualizer focuses on the Share Partition state machine: how individual records move through AVAILABLE → ACQUIRED → ACKNOWLEDGED → ARCHIVED, how the Share Partition Start Offset (SPSO) and End Offset (SPEO) advance, and how delivery count limits, acknowledgement modes, and consumer scaling interact.

⏸ PAUSED — hover over records to inspect
How to Use
  • Use the Topology controls to set partition count and the number of competing consumers.
  • Switch share.acknowledgement.mode to explicit to see RELEASE, REJECT, and RENEW acknowledgement types in action.
  • Lower share.delivery.count.limit to 2 or 3 to watch records hit the ARCHIVED state quickly after repeated redelivery.
  • Hit ⏸ Pause (or press Space), then hover over any record cell to inspect its partition, offset, state, delivery count, and lock status.
  • Click ⚡ Crash Consumer to simulate a session timeout — acquired records return to AVAILABLE without acknowledgement.
  • Click the i icon next to any setting for a description from the Kafka documentation.
